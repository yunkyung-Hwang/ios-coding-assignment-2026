# ADR-0002: 모듈 경계

상태: 채택

## 맥락
- 요구사항이 원격·로컬 데이터 책임 구분 명시
- 아키텍처 패턴은 자유

## 결정
- Features / Domain / Core 3계층
- `ProductFeature`(화면), `FavoriteKit`(화면 없는 도메인), Core 4모듈
- 계층 판별
  - 화면이 있으면 Features
  - 화면 없이 도메인을 소유하면 Domain (규칙·영속·공유 상태 포함)
  - 도메인을 모르면 Core

## 근거
- 경계 기준 세 가지를 모두 통과할 때만 분리
  - 독립적으로 변경되는가
  - 여러 곳에서 공통 접근하는가
  - 데이터 소유권이 다른가
- 찜은 셋 다 해당. 로컬 관리 명시, 목록·상세 공통 접근, 원격과 소유권 상이
- 목록·상세는 상품 API 변경 시 함께 변함 → 한 모듈
- `FavoriteKit` 은 `Set<String>` 만 취급, 상품 미인지 → 다른 도메인 추가 시 수정 불필요
- 판별은 도메인을 "아는가" 가 아니라 "소유하는가" 로 한다.
  ProductFeature 도 상품 도메인을 알지만 화면을 가지므로 Features 다.

## 기각한 대안
- **단일 타겟 + 폴더 분리** — 책임 구분이 폴더 관습에만 의존. 잘못된 의존을 컴파일러가 막지 못함
- **화면 단위 분할(목록/상세 별도 모듈)** — 두 화면이 같은 API 변경에 함께 반응하므로 경계가 인위적
- **찜을 상품의 속성으로 포함** — 다른 도메인에 찜을 붙일 때 상품 모듈을 수정해야 함

## 트레이드오프
- 타겟 수 증가로 초기 설정 비용 발생
